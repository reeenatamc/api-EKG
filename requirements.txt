# Runtime dependencies for api-EKG.
#
# THIS FILE IS NOT THE WHOLE STORY. The worker imports ``ecg_pipeline`` in-process, which
# pulls in torch and numpy under a pinned ABI (numpy<2 with torch<2.4; relax one and you
# must relax the other). So these packages must be installed into the SAME interpreter
# that already has ecg-pipeline -- see README, "Environment".
#
# Everything below is pure Python and has no binary dependency, which is why adding it to
# that interpreter cannot disturb the pinned stack.

# 5.2 is the LTS, supported to April 2028. The previous bound was <5.2, which sat one
# release below it and could not be satisfied at all alongside the admin theme below.
django>=5.2,<6.0
djangorestframework>=3.16

# Admin theme. Pin the upper bound: this package tracks Django closely and every release
# from 0.97 on requires django>=5.2, so an unbounded install re-resolves Django rather
# than failing. It did exactly that here once, jumping 5.1 to 6.1 without a word.
django-unfold>=0.100,<0.110

# The app runs on Expo. On a device React Native does not enforce CORS, but `expo start
# --web` runs in a browser and does, so without this the web target fails against a
# backend on another origin while the device target works -- a confusing way to lose an
# afternoon.
django-cors-headers>=4.3

# The three below are used by this service's own code, not only by the pipeline, and were
# missing: in the environment the README describes they arrive through the digitizer's
# virtualenv, so a clean install is the only place their absence shows. It shows loudly.
# Without Pillow the service does not start at all; without the other two, three test
# modules fail to import and `manage.py test` reports 56 tests instead of 117 -- the same
# silent-skip that ecg-pipeline's README warns about, happening here.

# studies.Study.image is an ImageField, and Django refuses to run the system check
# without Pillow: "Cannot use ImageField because Pillow is not installed".
Pillow>=10

# analysis/rectify.py builds the homography with it, and analysis/calibration.py the
# amplitude scaling. Kept below 2.0 because the worker shares its interpreter with torch
# 2.2.x, which is built against the numpy 1.x C ABI and fails to import under numpy 2 --
# the same pinned pair the README describes.
numpy>=1.26,<2

# analysis/calibration.py resamples with it, per continuous run and never across a NaN.
#
# The upper bound is not caution either. scipy 1.16 and later require numpy>=2, so an
# unbounded install resolves to a scipy that contradicts the numpy pin three lines up,
# in this same file. pip installs it anyway and says so in one line among many:
#
#   scipy 1.18.1 requires numpy<2.8,>=2.0.0, but you have numpy 1.26.4
#
# What is left is an environment that imports fine until something reaches the part of
# scipy that needs the newer numpy.
scipy>=1.12,<1.16
